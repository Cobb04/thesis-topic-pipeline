# 二维筛选与三道关卡

## 一、两个轴怎么打分

### 横轴反过来的"空位度"

空位度 = 拥挤度的反面。直接用第 3 步的计数，不用另外打分。

### 纵轴"好写度"的四个分量

| 分量 | 判断标准 | 权重建议 |
|---|---|---|
| 数据可得 | A 股或 A+H；年报与 ESG 报告能免费下载；五年连续 | 高 |
| 议题具体 | 行业有天然可写的议题（碳、水、食品安全、供应链、尾矿……） | 高 |
| 财务规范 | 标准无保留意见；业务能看懂；科目能勾稽 | 中 |
| 专业门槛 | 不需要补大量行业知识就能读懂报告 | 中 |

四分量各 1—5 分，加权平均。**不要用总分排序**，要放进矩阵看位置。

## 二、四象限与动作

```
              空位多 ←——————————→ 空位少
好写度高  │  ① 首选           │  ③ 陷阱                        │
          │  直接进第 5 步     │  资料最好找，答辩风险最高       │
          ├──────────────────┼───────────────────────────────┤
好写度低  │  ② 备选           │  ④ 淘汰                        │
          │  先算工作量再决定   │  不要碰                        │
```

- **①**：进入关卡。多数情况会停在"可辩护的论文级延伸"。
- **②**：只有学生明确接受工作量时才选。典型代价是境外子公司数据、行业技术门槛、监管口径复杂。
- **③**：本流程要防的主要错误。看起来最舒服，实际最难答辩。要留就先把切口换掉（见 `refinement-blueprint.md`）。
- **④**：直接排除。

## 三、关卡一：贡献层级

不要因为"大方向有人写过"就毙掉。先分清两件事：

- **已知的宽泛想法**：这类题、这个机制、这个政策问题以前出现过。
- **已耗尽的具体设计**：X、Y、数据、场景、方法、机制、贡献边界都被覆盖了。

只有第二种才够格毙掉。

| 层级 | 含义 | 动作 |
|---|---|---|
| 前沿增量 | 新测量、新冲击、更强识别、数量级估计 | 放行 |
| **可辩护的论文级延伸** | 新场景、新样本、测量改进、期间更新、描述性事实 | **放行（最常见）** |
| 仅可降级 | 只能做描述性/复现 | 降级后再做 |
| 已耗尽 | 具体设计被完全覆盖 | 换题 |

## 四、关卡二：答辩风险

必须写出一句话——导师或答辩最可能问的那个问题，并备好**带数字**的答案。

自检：你的答案里有没有具体的年份、篇数、数据范围？没有就是"角度不同"，等于没答。

常见问法与应答骨架：

| 问法 | 应答骨架 |
|---|---|
| "你和 XX 那篇有什么区别？" | 案例不同 + 样本期多 N 年 + 覆盖了某个制度窗口 + 做了对方没做的某项分析 |
| "这个行业不都差不多吗？" | 指出该公司的制度特殊性（A+H 双重披露、碳市场纳入时间、行业监管口径） |
| "你的结论能推广吗？" | 明说不能，单案例结论限于该案例，作为"机制存在性"证据 |
| "为什么不用回归？" | 说明论文类型是测量/事实类，无对照组，不做因果 |

## 五、关卡三：论文类型

先定类型，再谈方法。**不要把案例题硬套成因果题。**

| 类型 | 需要 | 不需要 |
|---|---|---|
| 因果实证 | 可信的识别策略（variation 有名字、假设可见） | — |
| **测量 / 事实** | 测量规则 + 数据路径 | 识别策略、DID、回归 |
| 理论 | 可建模的原语 + 命题 | 数据 |
| 政策报告 | 事实与制度梳理 | 识别 |

判成"测量/事实"类，就在开题里写死一句"**本文不做因果推断**"。这句话能挡掉一半不必要的攻击，也让"没有对照组"从缺陷变成边界声明。

## 六、两层判定词

判定要分两层，不要把可行性和决策混成一句话。

**可行性颜色**

| 颜色 | 条件 |
|---|---|
| 绿 | 问题一句话说得清；数据/测量路径可信；核心变量有定义；最小版本赶得上截止日；正负零结果都能解释 |
| 黄 | 方向有价值但需修：题太宽、数据访问未确认、测量假设偏强、机制太多、只能支撑弱因果 |
| 红 | 关键变量测不了；数据拿不到或整理成本超期；最近文献已覆盖同一具体设计且无新增量 |

**决策**

| 决策 | 用于 |
|---|---|
| `proceed` | 数据、问题、范围基本可行 |
| `pivot` | 保留内核换设计 |
| `park` | 想法有价值但数据或时机未到 |
| `kill` | 核心变量/数据/贡献边界救不回来 |
| `upgrade` | 最小版本成立，可加更强机制或对比 |
| `downgrade` | 高端设计不成，但描述性/测量版可做 |

## 七、继续打磨还是冻结

在写开题框架之前先判这一句：

- **建议继续打磨** —— 停在评分和下一步选项，不要输出蓝图。
- **建议冻结当前版本** / **可以推进，也可继续升级** —— 才进入精修与蓝图。
- **建议暂停或更换路线** —— 回到候选池，不要硬救。

硬救一个该停的题，代价是整个开题周期。
