# 拥挤度实测

第 3 步的全部操作细节。这一步的产出是**数字**，不是印象。

## 一、查询配方

用知网专业检索（MCP 工具名通常是 `advanced-search`）：

```
keywords = "<主题词>"
subject  = "<公司简称>"
limit    = 15
sort_by  = "relevance"
```

要点：

- **不要把公司名填进 `keywords`。** 关键词字段里很少出现公司名，会返回空，从而误判"没人写过"。实测 `keywords="紫金矿业"` 与 `subject="紫金矿业 ESG"` 都返回空。
- `subject`（主题）比 `keywords`（关键词）宽，适合放公司名。
- 返回结果里 **`journal` 字段放的是学位授予单位**（如"河北地质大学"），不是期刊名。这是区分学位论文和期刊论文最快的办法。
- 每页 20 条。`limit` 超过 20 会自动翻页，也可以直接给 `max_pages`。

### 备选查法（上面返回空时按顺序试）

1. `title = "<公司全名>"` —— 近似匹配，结果杂，需人眼筛；但公司名常出现在标题里，最稳。
2. `keywords = "<行业词>"` —— 如"乳制品""水泥""钢铁""生猪"，看行业整体拥挤度。
3. `keywords = "<主题词>"` + `year_from` / `year_to` —— 看年度分布，判断是"每年都在写"还是"某年集中写过"。

## 二、每家公司必须记的三个字段

| 字段 | 怎么取 | 为什么要 |
|---|---|---|
| 同题学位论文数 | 标题含"问题/对策/质量评价/优化/动因/经济后果"的计数 | 分级依据 |
| 最近的一篇对手 | 单位 + 年份 + 角度 | 答辩时必然被问到 |
| 对手的样本期到哪一年 | 从摘要或答辩年份反推 | 决定你还有没有时间壁垒 |

第三项最容易被忽略，但它决定了"换个年份"能不能成为你的增量。**答辩年份减去 1—2 年，通常就是对手的数据上限。**

## 三、分级阈值

| 同题学位论文数 | 分级 | 默认动作 |
|---|---|---|
| 0—1 | 低 | 进第 4 步 |
| 2—3 | 中 | 必须换切口（测量对象、期间、制度窗口），否则弃 |
| 4—6 | 高 | 弃，除非有硬增量 |
| ≥7 | 饱和 | 直接弃 |

同时要看**角度分布**：如果 2—3 篇全是"质量评价"，说明方法位被占了；如果角度分散（动因/后果/评级），可能还有空间。

## 四、校准数据（2026-10 实测，n=5）

主题词 `ESG信息披露`：

| 公司 | 同题学位论文 | 最近对手 | 分级 |
|---|---|---|---|
| 伊利股份 | 8 | 西南财大 2024《…现状评价及**对策**研究》 | 饱和 |
| 贵州茅台 | 3 | 兰州财经 2025《…质量评价研究》 | 中 |
| 海螺水泥 | 3 | 西南民大 2025《水泥行业…**问题研究**》 | 中 |
| 牧原股份 | 2 | 兰州财经 **2026**《…质量评价及**优化**研究》 | 中 |
| 宝钢股份 | 0 | 仅《会计师》期刊 1 篇；同行业鞍钢 1 篇 | 低 |
| 紫金矿业 | 0 | 仅期刊 1 篇 | 低 |

读法：

- 热门消费股（乳业、白酒）必然饱和；矿业空但难写；钢铁居中偏空。
- 牧原那篇是 **2026 年**答辩的，说明"最新一年报告"这个壁垒正在快速关闭——每年都有人用上一年数据。

## 五、工具契约

### 调用顺序

```
login                       # 仅 stdio 模式且本会话尚未唤醒浏览器时需要
  ↓
advanced-search             # 拿候选清单
  ↓
get-info-from-url           # 对最接近的 1—2 篇取摘要，确认角度与样本期
```

### 参数映射

| 想查什么 | 传什么 | 备注 |
|---|---|---|
| 主题词 | `keywords` | 如 `ESG信息披露`、`碳排放` |
| 公司 / 行业 | `subject` | 比 `keywords` 宽，放公司简称或行业词 |
| 篇名精确找 | `title` | 近似匹配，适合已知标题时定位 |
| 年份窗口 | `year_from` / `year_to` | 传年份整数，不要传日期串 |
| 条数 | `limit` | 每页 20；超过 20 自动翻页 |
| 直接指定页数 | `max_pages` | 深层翻页用；旧版可能没有此参数 |
| 排序 | `sort_by` | `relevance` / `date` / `citation` / `comprehensive` |

### 部署要点（若要自己装）

- 服务器包：`cnki-mcp`（Python ≥ 3.11，依赖 Playwright）。
- 传输：`stdio`（由客户端拉起进程）或 `http`。MCP 客户端侧最小配置形如：

  ```yaml
  transport: stdio
  command: <venv>/bin/cnki-mcp      # Windows 为 Scripts\cnki-mcp.exe
  args: ["serve", "--transport", "stdio"]
  toolCallTimeoutMs: 180000         # 知网走真实浏览器，给足
  failOnStartupError: false         # 未登录时不要拖垮客户端启动
  ```

- **登录**：必须先初始化浏览器资料并完成学校/机构认证。校外访问走 **CARSI 统一身份认证**，不要点"IP 登录"——那需要校内 IP，校外必报"IP 不在许可范围"。
- **超时**：官方 `init` 只等约 120 秒，走 CARSI 不够用。直接用 Python API 调 `CnkiClient(profile=...).login(timeout=900)` 更稳。
- **profile 锁**：同一 profile 目录同一时刻只能被一个进程占用。第二个客户端会报"已在现有的浏览器会话中打开"；要么共享一个实例，要么各用独立 profile。
- 本文档不写死任何本机路径与 profile 名——换机器就失效。

### 已知缺陷

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回当天最新文献、与检索词无关 | 简检索（`easy-search`）不可靠，检索词不生效 | 只用 `advanced-search` |
| 报 `please call login before using browser tools` | stdio 模式每个新会话需先唤醒浏览器 | 先调一次 `login` |
| 年份过滤返回空 | 日期控件是 readonly 且要求 `yyyy-MM-dd`；旧版本会静默忽略筛选 | 见下 |
| 深层翻页拿不到 | 分页控件 `#PageNext` 的 `data-curpage` 是相对页码 | 用页码链接，或给 `max_pages` |

年份过滤的老版本缺陷（若所用版本未修）：日期输入是 `readonly` 的日期选择器、`maxlength=10`，直接塞 `"2024"` 既不进内部状态也不符合格式，筛选被忽略，随后本地按年份一过滤就空了。修法是解 readonly、写 `yyyy-MM-dd`、补发 `blur`；并把"年份未知"的记录保留而非丢弃。

## 六、没有库可用时

必须明说"未做库内实测，结论是临时的"，并把"连上知网"列为第一项任务。**不要**用公开网页搜索替代——它只能做点状核实（单篇是否存在），做不了面状查重。

可用的降级手段（按可靠性排序）：

1. **公开网页 + 学位授予单位官网**：少数高校把学位论文库对公网开放，能核实单篇。只能点状用。
2. **让模型给出检索式，由人代跑**：模型输出 `KY='...' and AF='...'` 这类表达式，人到库里执行后回传。慢，但数字是真的。
3. **公开的学科/行业综述**：只能判断"这个方向热不热"，不能判断"这家公司有没有人写过"。

三者都不能替代第 3 步。用了降级手段，必须在结论里标注来源等级。
